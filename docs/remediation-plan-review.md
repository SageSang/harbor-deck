# HarborDeck 修复改造方案

状态：联合终审草案，待 Sidney 审核；未授权实施、发布或操作真实数据。

基线：Web 1.4.19，提交 010024c5d4be0a2f6b0e87632326c2439e08e8d9。原审查与本次交叉审查基于这一实现；原任务报告的 182 项测试、lint 与构建通过属于旧版本基线，不能代替修复验收。真实 Chrome 扩展、反代及线上升级中断时间尚未核验。

讨论来源：[原审查任务](codex://threads/01a093a8-25c8-7d51-909e-0f44f8c03d3d) · [联合复核任务](codex://threads/01a093b0-56f4-7fe0-a37a-6dd3ad4449be)。本文取代前几轮方案中的“派生管理引用”和“每次新标签完整探测”默认路线。

**1. 建议批准的范围与顺序**

采用四批局部修复，保留单管理员、场景密码、共享书签、写入队列、ETag/If-Match 和访问版本缓存。各批有独立验收和回退条件；第一、二批优先组成服务端修复版。第二批若拖延，第一批可先发布；扩展商店审核不阻塞服务端修复。

| 批次 | 具体目标 | 不改的后果 | 主要修改位置 |
|---|---|---|---|
| A 权限与数据一致性 | 统一可见候选及新增引用校验；认证事务；恢复后的会话失效 | 隐藏内容隔离、并发配置保存和访问撤销仍不可靠 | server/integrationApi.ts、app.ts、auth.ts、sceneAccess.ts、configStore.ts；恢复提交涉及 webdavBackupManager.ts |
| B 服务与备份可靠性 | 完整响应超时；服务监听与远端调度分离；提交结果、清理结果分别报告 | 自动备份的远端故障仍可能拖住服务启动或备份队列 | server/webdavBackup.ts、webdavBackupManager.ts、app.ts、index.ts；备份响应与界面 |
| C 编辑体验 | 分字段确认草稿；新建/复制后选择正确场景；防止旧响应回填 | 尚未保存的输入仍可能丢失，新分组可能建到旧场景 | src/features/config/useFieldDraft.ts、src/components/BookmarkManageButton.tsx、src/features/navigation/useNavigation.ts |
| D 扩展与接口兼容 | 地址缓存、弹窗初始化、受限内嵌、历史长标识；独立维护依赖 | 切网、已有书签识别、内嵌及长标识管理仍有缺口 | extension/src；server/bookmarkManagementApi.ts、bookmarkManagementService.ts；生成器、OpenAPI、package*.json、Dockerfile |

D 拆成扩展、长标识、依赖三个可独立验收的改动。无需引入新的认证框架、持久化任务系统、ID 映射库或前端状态框架。不自动清理历史共享、不全量迁移配置、不截断历史 ID、不扩大管理 Token 权限、不全局放宽 Cookie。

**2. 对现有能力与服务的影响**

这里的“非保护场景”仍要求管理员登录 Web；不是互联网匿名可读页面。

| 能力 | 保留的行为 | 必要变化、操作负担与兼容边界 |
|---|---|---|
| 管理员登录、场景解锁 | 原账号、Cookie 名称、场景密码与单管理员模型 | 更新服务后内存会话消失，需要重新登录和解锁；改密保留当前操作端新会话，其他会话失效；限流按可信代理解析出的客户端分桶，同 NAT 仍可能共用额度 |
| 共享书签 | 跨场景引用、解锁后主动共享；修改影响保护场景的共享元数据仍须解锁 | 搜索/扩展 Token 收藏与隐藏记录相同的 URL 时创建独立记录；不复制隐藏字段；无权新增的引用整笔拒绝 |
| 搜索/uTools | 现有接口、Token、Header、非保护内容搜索 | 原 Token 无须轮换；重启期间可能短暂请求失败；新旧客户端兼容 |
| AI 管理 API | 独立管理 Token 全场景整理、版本检查、dry-run、正常短 ID 路由 | 仅新增 4 个长书签 slug 的原始 ID 写入口，读取用 /state；历史长 slug 客户端按需采用；不承诺所有超长 scene/group 路径均已兼容，不增加场景 CRUD |
| 扩展快捷收藏 | 当前页收藏、多场景放置、快速记录、已有书签编辑 | 旧设置、语言、Token、真实草稿保留；保存响应不明确时先只读核对，无法确认则保留草稿并提示核验，不自动重复写入 |
| 扩展直达与网络切换 | 新鲜成功缓存快路径、主备地址、地址栏输入保护；Web 手动网络模式 | 自动快路径的成功缓存窗口从 24 小时缩短为 30 秒，因此间隔超过 30 秒且无后台成功刷新时会更多进入约 400ms 默认冷路径。仍不能保证窗口内切网首开必达；已跳离后不能保证追回失败导航 |
| 扩展内嵌 | 保留 embedded 选择和 iframe 使用方式 | 服务端登记可信扩展 ID；主备地址权限按需授权；重装解压扩展可能需更新 ID。跨 origin 是否共享登录状态以真实 Chrome 验收为准；失败提供主动打开入口，不静默改设置 |
| 历史配置、引用、备注与链接 | 原 ID、顺序、人工内容、共享引用、JSON 导入和备份恢复 | 不要求用户先整理数据；旧缓存可重建，业务数据不迁移。历史共享无法仅凭现状判断是否由缺陷产生，不自动删改 |
| WebDAV 备份 | 原周期、版本保留和手动备份 | 远端失败不阻止 Web/API 启动；单请求完整截止时间可能影响慢链路，提供有界部署配置；上传成功与版本清理失败分别报告 |
| WebDAV 恢复 | 继续恢复所选完整版本 | 提交时与最新 auth 比较：相同则保留管理员登录，变化才撤销；每次恢复清空场景解锁。远端调度不推迟本地结果与失效处理；恢复仍会替换当前配置，沿用显式恢复确认 |
| 部署与回滚 | 原单实例部署和配置卷 | 容器停止至服务健康有中断，时长待同环境测量。旧服务回滚会重新带回隐私缺陷，优先准备保留 A 批修复的回退版本 |

**3. A 批的具体设计与验收**

权限处理只调整现有边界：lookupIntegrationBookmark 与 createIntegrationBookmark 先过滤可见候选，再匹配主/备用 URL。隐藏同 URL 新建时仅采用本次提交的内容。Web 导航与整站两个保存入口在现有写事务内，以提交前的可见性检查新增引用，保留隐藏场景占位符合并；拒绝时不改变文件与 revision。管理 Token 原有的全场景能力独立保留。

认证的昂贵哈希仍在锁外完成。setup 在锁内再次检查账号是否存在；改密最终确认原会话有效、已验证凭据仍为当前凭据，再只合并最新 system.auth。同期保存的主题、WebDAV 等设置不被覆盖。setup、改密和场景密码变更成功后所需的旧凭证失效，也在本次成功提交的同步延续中完成；需要新管理员会话时先失效旧会话、再签发当前操作端的新会话，然后释放队列。提交失败不改变会话，HTTP 响应在事务外生成。

新增小型 inspectAppConfig 入口：复用现有写队列取得最新快照，执行同步检查并返回，完全不写盘。登录的最终检查与内存会话签发使用这一入口，不调用会写盘的 mutateAppConfig。同步回调不做网络、哈希、HTTP 响应或再次进入队列。

认证指纹表示实际用户名与密码哈希，用于绑定会话及核对已验证的凭据；不再增加管理员代次或持久版本表。场景保留必要的内存失效代次，配合当前密码状态和原会话检查，处理密码未变但访问已清除的情况。单场景锁定只取消该会话、该场景的访问和待完成解锁；恢复或已有全局 clear 语义才全量失效。普通书签、主题和调度变化不使登录失效。退出后，绑定原会话的迟到解锁或改密在最终处理前重新核对 sessionKey。独立匿名登录没有共同会话身份，不能承诺被另一条退出请求自动取消；本轮不增加客户端登录请求协议。

登录和场景解锁在哈希前预占在途额度，在 finally 释放；保留原失败阈值、窗口和封禁周期，成功不抹掉其他在途占位。使用现有 trustProxy 约束下的 request.ip，不直接信任 X-Forwarded-For、不扩大可信网段。[Fastify 官方说明](https://fastify.dev/docs/latest/Reference/Server/#trustproxy)

恢复由 app 组合层向备份管理器注入窄接口 commitRestoredConfig。事务内读取提交前最新配置、检查取消状态并提交；rename 成功的延续中，在后续异步清理前执行本次提交专用的同步内存失效。store 不导入认证服务，不建设全局 hook 总线。安全回调必须短小、同步、无外部 I/O；提交后的异常不能被描述成“文件未恢复”。远端重排调度在事务外。

A 批通过条件：正常共享/解锁后共享、搜索与管理 Token 能力对照通过；两个保存入口的拒绝结果整笔不写；隐藏记录不遮挡合法同 URL 候选；并发初始化只有一个成功；改密保留同期系统设置；登录检查不修改配置文件或 mtime；登录签发时已验证的用户名/密码哈希仍与最新配置一致，绑定原会话的改密/解锁仍须有有效会话，场景锁定及 clear 取消其覆盖范围内的在途解锁；可信/不可信代理与在途限流正确；auth 不变的恢复保留登录，场景仍全部重新解锁；恢复后的调度失败不延迟安全失效。管理员登录按签发时当前凭据判断，不记录凭据曾改变又恢复相同值的历史，也不承诺撤销没有共同会话身份的匿名登录。

**4. B 批的具体设计与验收**

requestWebdav 将响应头、需要读取的成功正文及错误正文纳入同一次截止时间。无需读取的成功正文及时取消或释放，不为丢弃正文额外等待。统一清理计时器、AbortSignal 和连接资源。默认单请求 15 秒；慢链路使用有界的部署级超时选项。整次备份包含多个请求，不能承诺总计 15 秒结束。

服务完成监听后启动远端调度，后台异常均有处理。保留一个备份队列、7/30/365 天周期、长等待分段与一小时重试。普通配置已保存或恢复已提交时，后续调度失败单独报告，不误报保存失败。上传已确认成功但列版本或清理失败时，保留新版本信息与清理警告；远端写请求超时属于结果可能不确定，不声称远端一定没有变化，也不盲目自动重复恢复。

在受控 SIGTERM/SIGINT 入口调用 app.close()，于 preClose 阶段停止接收备份任务、取消远端请求和未进入提交阶段的恢复；onClose 仅负责最终资源清理。在发起 rename 前再次检查停止状态；已经发起的 rename 必须等待结算，成功后完成同步访问失效，再结束优雅关闭。保证适用于正常优雅关闭，不承诺强杀、掉电或已经开始替换后的回滚。

B 批通过条件：慢响应头、慢正文、错误正文停住均可结束；自动备份配置下远端不可达仍可启动 Web/API；队列失败后后续操作可继续；长周期和重试保持原语义；关闭的排队、待提交、已开始提交三种时点有明确结果；成功提交与调度/版本清理失败分别显示；正常备份、旧备份恢复、保留版本、大文件及慢链路配置通过。

**5. C 批的具体设计与验收**

按组 ID 保存 base/draft/latest，并给提交携带表单所属场景、访问版本和操作编号。成功只确认提交字段；请求发出后用户继续输入的内容和其他字段保持 dirty。服务端规范化值更新已保存基线。干净字段接收远端刷新；脏字段遇到远端变更/删除时保留输入并明确冲突。412 不自动重发、不把整份草稿标成已保存，不增加日常确认框。

导航保存成功先处理服务端的脱敏配置和新 revision，再执行新建/复制后的选择。仅写入提交时捕获且当前仍有效的精确访问版本缓存。取消旧读取后，检查查询实例/数据更新次数及提交基准；不能证明安全采纳时重读权威状态，不能给内容 hash 推断时序。保留现有权限变化时取消/移除旧查询的机制，不把私密快照广播到所有访问版本。

保存成功、页面重读失败必须分开反馈，提供仅重读入口，不回滚或再次创建。选择的新场景需存在于最终采用的配置；被其他操作删除时仍执行现有回退。切换场景、访问变化、关闭重开使过时表单回调失效。使用共享保存 hook 的书签编辑、服务网格、快速记录一并做回归。

C 批通过条件：A/B 同改只保存 A；保存期间继续输入；远端增删改组与 412；新建/复制的慢网络、保存失败和刷新失败；旧读取/并发响应乱序；登出、锁场景、关闭重开后旧回调不回填。使用真实 QueryClient 的组件集成测试验证交互，不把引发竞态的 hook 全部 mock 掉。

**6. D 批的扩展默认行为**

以下是推荐设计预算，均未实测。控制器计时从本次设置和缓存读取完成开始；另行测量“新标签创建到导航提交”的总耗时，warm 总耗时约 150ms 仅为待测目标，不能把控制器预算当作完整用户等待。保留轻量 loader、预连接和输入保护。

| 状态 | 默认行为 | 地址决策预算 |
|---|---|---|
| 同设置版本、最新结果成功、成功验证在 30 秒内，且无更新失效标记 | 快速使用成功地址并后台刷新；导航前收到有效新结果可采纳，不延长窗口 | 保留 120ms 输入保护，新增网络等待 0ms |
| 冷启动、过期、版本不匹配或最新结果已失败 | 主备并行探测；有成功结果才进入自动选择 | probeTimeoutMs + 200ms；默认 400ms，现有 50–5000ms 配置对应 250–5200ms |
| 冷路径快速选出地址 | 达到输入保护窗口后打开，不等满预算 | max(180ms, 选定结果到达时刻) |
| 双失败或截止仍未知 | 保留本地壳、主备地址、重新检测和上次成功地址的手动入口 | 截止后不安排迟到自动跳转 |
| 浏览器明确报离线 | 取消本次自动资格，显示手动入口；恢复在线不会静默重启已取消的跳转 | 及时进入本地状态，约 150ms 为待测目标 |
| 未配置地址 | 显示设置入口 | 不探测、不跳转 |
| 仅配置一个地址或无法获得探测权限 | 保留明确的未验证地址打开能力；不得将它记为成功缓存 | 沿用 180ms 输入保护；不为无法执行的探测空等完整预算 |
| 已输入/粘贴/组合输入，或页面隐藏/离开 | 本次自动跳转持续取消；检测仅更新可选入口和以后缓存 | 新结果不重新启动自动计时；iframe 已呈现后也不迟到换址 |

主地址验证成功即可选定；备用先成功时，等主地址明确失败或其探测截止后采用备用。缺权限不等于失败，有已验证的可用地址时优先使用它。同设置版本下，尚未被后续成功验证解除的明确失败，优先于单地址/缺权限例外：能探测则走冷路径，不能探测则仅留手动入口。无明确失败记录时，才保留原有未验证自动打开能力。未验证路径独立于成功缓存。保持 Web 手动内外网模式，不把扩展决策改成第二套书签地址规则。

明确残余风险：30 秒成功窗口内，120ms 刷新没有完成时，切网后的首次打开仍可能采用旧成功地址。导航提交后无法保证由扩展追回；需要用户重新打开或选择另一入口。30 秒是内部默认常量，不增加用户设置；比原 24 小时窗口更常探测，是减少旧地址持续使用与保持热缓存速度的折中。旧成功地址最多沿原 24 小时期限保留作手动候选，不凭该期限取得自动跳转资格。自定义 5000ms 的冷路径可能等待约 5.2 秒，这是保留慢链路设置的影响。

缓存只增加必要版本信息：schemaVersion、非秘密的 settingsRevision、verifiedAt、lastAttemptAt/status。只有实际验证成功才更新 verifiedAt；旧缓存作为未验证候选重建，保留设置、Token、语言、embedded、真实草稿和 smartHarbor 迁移。Service worker 按设置版本合并任务并串行提交地址缓存/快照，提交前与消费者均核对版本；旧任务不能采用新配置名义提交。先提交地址，再独立获取主题，主题超时不占地址预算。

弹窗初始化不依赖其加载出的语言重复执行。设置读取、真实草稿恢复及已有书签查询结束前，禁止初始值自动落成草稿；迟到结果不覆盖用户输入。切换实例时不自动使用另一实例的分组 ID。GET 网络失败可重新探测并有限重试一次；认证/权限错误保持明确反馈。POST 结果不确定时保留提交快照并先只读核对，不能唯一确认就由用户核验，不能自动切地址再写。此阶段不引入幂等键系统。

内嵌采用精确可信扩展 ID 的服务端配置。普通页面默认拒绝嵌入，只对必要 HTML 入口生成允许指定扩展来源的 CSP；embedded=1 不是授权凭据。设置页显示实际扩展 ID，商店版/解压版分别登记，明确重装后的维护方式。保留当前 Cookie 策略；强制 frame-ancestors 的优先规则按 CSP 规范处理，反代追加限制需核验最终响应。[CSP 规范](https://www.w3.org/TR/CSP3/#frame-ancestors-and-frame-options) · [Chrome 存储与 Cookie 说明](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)

扩展发布门槛：真实 Chrome 的商店/解压安装、HTTP LAN/HTTPS、反代、host permission 允许/撤销、第三方 Cookie 设置下，登录、刷新、退出、场景解锁通过；非可信来源仍不能嵌入。测量 warm/cold/离线完整时延，并验证无新增快路径网络等待、迟到结果不跳转、用户输入不被抢走。兼容未通过时阻止该功能发布，保留设置与主动打开入口，不默认移除内嵌能力。

**7. D 批的长标识兼容和依赖维护**

继续保存和传递原始 ID，不采用派生管理引用、ID 映射、自动重命名或全量迁移。读取复用 /state，现有创建、batch-place、fill-missing 等请求体接口直接保留。batch-place 不能替代带 position 的单项放置；逐场景删除不能替代原子的全局删除。

仅新增下列 4 个写入口，统一前缀 /api/management/v1，直接转交现有 Service 与 executeWrite。slug 始终定位旧对象；patch.slug 或 options.slug 才表示新标识。读取用 /state，不再加精确读取接口。

| 拟新增入口 | 请求体 | 语义 |
|---|---|---|
| POST /bookmarks/update | { slug, patch } | 修改原书签，原 ID 未变可继续使用长值 |
| POST /bookmarks/delete | { slug } | 一次原子全局删除 |
| POST /bookmarks/duplicate | { slug, options } | 复制原书签，生成的新 ID 受新建规则约束 |
| POST /bookmarks/set-placement | { slug, sceneId, groupId, position? } | 含位置的放置或移动 |

其余现有批量能力继续承担原有操作；普通父 ID 下，单项移除可以调用 batch-remove 并只传该书签。兼容范围明确为长书签 slug 的读取、修改、复制、全局删除和含位置放置。长 scene/group 作为上述请求体中的定位符可用，但其他仍把父 ID 放路径的分组、排序、快速记录等接口不在本批扩展范围，不宣称已经全覆盖；其既有正常能力不变。后续若有实际需求，再独立评估静态别名，不增加通用命令框架或原来没有的场景 CRUD。删除使用 POST，不依赖 DELETE body。

别名沿用同一管理 Token、读写限流、1 MiB 请求体、If-Match、dry-run、错误码、orphanPolicy 和单事务原子性；不复制第二套业务逻辑。query 也受总 URI 限制，不作为任意长度的保证。保留原路径路由及 256 限制，现有客户端无需改；历史长标识可改用兼容入口，回滚旧服务后该新入口不可用但原数据仍在。

新建/显式改 ID 的入口与生成器限制最终结果不超过 256，包含复制与唯一性后缀的空间；旧 ID 未变的普通编辑继续接受。共享的持久化/引用 schema 不加追溯上限，历史 JSON 导入、整配置保存和备份恢复保持旧值。浏览器书签导入创建的新对象走新生成器，保留原有拼音/规范化规则。长度与路由的已解码参数定义对齐，不把 UTF-8 字节、百分号编码长度和 JavaScript 字符串长度混为一谈。

兼容发布门槛：256/257/4096 字符旧书签在本批承诺范围内的读改删/复制/放置、原短 ID 路由、引用原子更新、dry-run、412、重启、JSON 导入和恢复；含定位符的完整 body 超过 1 MiB 时明确 413 且不写入。极端超体积记录的在线编辑不承诺，但存储与读取不被此次校验破坏。OpenAPI 区分新建标识约束、历史引用和路径承载限制，列出未扩展的长父 ID 路径边界。

依赖独立更新：依据实际锁定版本和上游兼容修复，处理 Fastify、fast-uri、js-yaml；globals、typescript-eslint 等检查工具移到开发依赖。告警不等于已经证明项目接口可触发。Docker 构建完整安装，运行层 --omit=dev 后启动、静态页面、认证、API 与备份均需验证；不借机做无关大版本升级。
