# 书签缓存与本地新标签页（1.4.26）

新标签页现在直接运行随扩展打包的正式前端。有缓存时，第一个可见界面就是原来的导航界面；连接后在当前界面更新书签、分组和顺序。不会显示独立缓存列表，也不会加载隐藏 iframe 或自动跳到服务端页面。

没有缓存时先显示可输入的过渡界面。内容就绪后接续文字、光标选择、输入焦点和 Enter 操作；中文输入法尚未结束组合输入时不移走输入框。搜索文字、当前仍有效的场景、分组展开状态、滚动和现有编辑草稿不因后台更新被清空。

## 使用与升级

1. 本轮焦点与主题修复需要将扩展升级至 1.4.26；可继续配合 1.4.25 服务端使用。可以先升级服务端，旧扩展继续按原方式使用；新体验需要更新扩展。Docker Compose 的端口、挂载和已有环境变量不用因本次改造更改。
2. 原连接地址、收藏 Token、检测时限和收藏草稿保留。旧内嵌模式及旧版默认直达模式自动使用本地页面；如确实需要跳转，在扩展设置中重新选择“直接打开”并保存。
3. 主备地址分别授权。首次需要时使用原服务端账号登录；沿用浏览器 Cookie，收藏 Token 不作为管理员登录凭据。登录状态在不同地址间是否相同取决于各自的 Cookie。
4. 成功读取后自动建立本机缓存。断网时仍可搜索、切换普通场景、展开分组、打开书签；恢复连接或点击“重新检测”后原位更新。右键菜单保留主备链接，编辑操作在完整配置可用后启用。
5. 修改连接设置后，在新标签页继续。旧页面停止提交，保留尚未提交的编辑内容。收藏保存结果不确定时保留草稿，核对结果后再决定是否重新提交。

新标签页和收藏读取不再依赖短时健康探测成功：实际 API 读取有独立的 5 秒时限。既有 200/1000 毫秒探测设置不会被擅自重置；它仍用于显式直达模式和设置中的地址检测。新标签页选定连接后，写操作固定在该连接，不在超时后自动换地址重发。主备地址应指向同一部署；跨网后旧地址不可用时，打开新标签页会重新选址。

## 新建标签页的焦点与主题

1.4.26 修复 1.4.25 本地模式未取得实际键盘焦点的问题。Chrome 原生新标签页入口优先把键盘交给地址栏；扩展入口现在在渲染前立即替换为本地 `newtab.html`，然后聚焦可见搜索框。这个本地入口不读取配置、不访问服务端、不显示另一套内容，也不增加历史记录。地址栏会显示扩展的本地页面地址；正式界面显示后的缓存刷新仍在同一文档内完成。

缓存首屏和无缓存过渡输入都可直接输入；方向键、`/`、Escape 和 Alt+Shift 场景切换沿用原行为。主动用 Ctrl/Cmd+L 切到地址栏、打开对话框或切到其他标签页后，后台数据到达不会抢回焦点。输入法组合输入期间的方向键交给输入法。

本地新标签页默认使用白色 Frost 主题，与操作系统深色模式、服务端默认主题分开。1.4.25 会把自动回填的深色值存成用户偏好，无法可靠区分旧手选值，因此升级后首次使用本地模式统一以白色开始；仍可在页面设置里选择 Midnight 或 Ember，之后会记住主动选择。普通服务端网页及其已有主题设置保留。

## 缓存范围与数据保护

网页仍使用 localStorage，扩展使用 chrome.storage.local。主备地址各保留一份最近成功的展示快照；快照增加图标、打开方式、搜索配置和展开状态，旧快照仍可读取。没有数据库、差量同步协议、轮询、离线写入队列或额外认证服务。缓存损坏时回到可输入的启动界面；存储空间不足或写入失败时，当前页仍可使用，但不承诺下次重开有最新副本。

只缓存普通场景实际引用的书签、分组、快速记录和显示配置。受保护场景即使解锁也不落盘；密码、场景令牌、管理配置和 WebDAV 凭据不进入快照。它不是备份，也不是离线权限凭证；断网期间无法立即获知远端权限变化。

展示快照不会填入可提交的完整配置缓存，不携带可写版本号。编辑和保存仍读取服务端完整配置并使用现有版本冲突检查。网络失败、坏数据和超时保留已有展示；成功返回的删除或空内容按实更新。

退出、账号变化或明确权限丢失会清除缓存并使旧请求失效；退出完成后再次清理，防止同时打开的标签页把旧结果写回来。手动清缓存不删除连接设置、收藏草稿或服务端书签。再次在线读取成功后会重新建立缓存。

## 发布包与回退

商店上传使用 `-store.zip`，其中不包含 manifest 的 `key`；保持使用原商店条目。手动解压安装使用不带 `-store` 的对应 Chrome/Edge ZIP，以保持固定扩展身份。

回退前导出连接设置和收藏草稿。新版本没有改变服务端配置格式；旧扩展仍可使用原有 API/内嵌入口，但会恢复旧的多阶段启动体验。旧扩展没有 `local` 选项时，在其设置里明确重新选择支持的打开方式。

普通网页仍须先加载网页程序；本次未增加 PWA，不能承诺普通 HTTP 地址在完全断网后仍能加载应用资源。扩展的正式前端已经本地打包，不受这项边界影响。
