# 1.4.26 新标签页焦点与主题回归验证

1.4.25 改为本地页面后，过渡输入没有初始聚焦，缓存首屏又关闭了 React 自动聚焦。Chrome 原生新标签页还会把实际键盘焦点留给地址栏，因此只补 `input.focus()` 也不足以修复。此前直接访问扩展 URL、主动填充输入框的测试没有覆盖原生新标签页入口；方向键组件测试通过不能证明新建标签页就能接收键盘。本轮补齐该验收入口。

主题问题来自新的扩展 origin 无法读取原网页 localStorage，同时服务端默认深色值被自动持久化为用户选择。本轮本地模式默认白色，单独记住主动选择的主题；不改普通网页偏好，也不强制修改服务端配置。

## 修复范围

扩展仅增加一个空的本地入口，在展示前用 location.replace 打开同包的 newtab.html。该入口不读配置、不发网络请求、不展示缓存 UI、不增加返回历史。缓存和在线数据仍共用同一正式文档。加载器聚焦可见的过渡输入，缓存首屏聚焦正式输入；已有交接继续保护文本、选择范围和输入法状态。复用一次性的焦点保护，不增加轮询、全局快捷键权限、浏览器输入监控或后台强制聚焦。

本地主题使用独立偏好键，缺失、损坏或存储失败时回到白色。1.4.25 自动写入的旧主题值无法区分主动选择，因此首次升级本地模式回到白色，主动重新选择后持久保留。主题变化不改变服务器数据或其他网页的选择。

## 检验方法与边界

隔离 Linux Xvfb 显示器、独立浏览器 profile、Chrome for Testing 153.0.8010.12，真实临时 HarborDeck 服务端及虚构账号/书签。使用 XTest 系统键盘事件 Ctrl+T 新建标签页，并在未点击、未调用 locator.fill 或 input.focus 的情况下键入文字。对实际页面禁用自动化的焦点模拟，同时验证 document.hasFocus 和文字确实进入目标输入框。辅助键盘脚本只连接隔离显示器，不向日常桌面发送按键。

旧版 1.4.25 实际扩展包复现焦点留在地址栏、页面输入框为空。独立对照确认原生覆盖入口里的 autofocus、focus、window.focus 不能接收物理输入；先打开本地普通扩展文档后可以接收。Chrome 官方说明见 [Override Chrome pages](https://developer.chrome.com/docs/extensions/develop/ui/override-chrome-pages)。

Chrome 与 Edge 身份构建均在上述 Chromium 中验证；不将 Edge 身份等同于 Microsoft Edge 本体。没有验证实际 MacBook、macOS Command 键、生产 NAS/反代或商店升级，没有代为部署。

## 回归结果

- 63 个测试文件、360 项自动测试通过；Lint、网页与服务端、Chrome 与 Edge 扩展构建通过。
- 原生新标签页缓存首屏直接接收文字；上下键进入首尾书签，左右键切换书签，Escape 与 `/` 返回搜索；Enter 搜索及打开书签。
- Alt+Shift+数字与 Alt+Shift+左右切换场景；保护场景弹窗保持键盘边界；组合输入的方向键不会导航书签。
- 断网缓存首屏、无缓存慢加载均可直接输入；组合输入结束后保留文字、选择方向和实际键盘焦点。
- 主动 Ctrl+L 后后台更新不抢焦点；慢加载交接也不抢地址栏；后台新建标签页不影响前台输入。
- 旧版自动深色偏好不再覆盖白色默认；实际设置页选择深色、白色后，新标签页保持各自选择。

上述原生键盘与主题流程在 Chrome、Edge 身份包中各通过 13 组检查。原有登录、缓存保护、增量更新、编辑、保护场景、收藏、跨标签页退出及 401 清理流程复用上一版隔离服务端脚本回归，Chrome 身份 HTTP、Edge 身份 HTTPS 各 13 项通过；另有 7 项连接失败、慢备用地址、设置变更冻结草稿、坏缓存、错误 Token 和显式直达恢复流程通过。HTTPS 测试使用临时证书与仅测试进程放行，不代表生产证书链已验证。正式包仍验证固定身份、商店包无 key、资源齐全及两个包除 manifest.key 外内容一致。具体发布结果以 Release 和 CI 为准。
