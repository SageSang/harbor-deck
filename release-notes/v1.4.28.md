# HarborDeck 1.4.28

## 中文

- 修复导航页打开后持续占满一个 CPU 核心的问题：显示设置的缓存同步会因字段顺序差异反复写入并触发渲染。相同内容现在不会重复写入，缓存通知也不会触发旧设置回写。
- 隔离 Linux Chrome 中，120 张测试书签的单页静置主线程忙碌率由 99.76% 降至 0.34%；双页各由约 99.7% 降至 0.23% 和 0.35%。5 秒静置窗口内缓存写入降为 0。这些是本地测试结果，Mac 实机仍需升级后复验。
- 普通网页及扩展直达模式请升级服务端至 `ghcr.io/sagesang/harbor-deck:1.4.28`，然后重新加载已有页面；扩展本地新标签页模式请升级扩展至 1.4.28。沿用原有端口、配置挂载、地址、Token 和书签，无需清空缓存或重置配置。
- Chrome、Edge 各提供解压包和 `-store.zip` 商店上传包。商店包不含 `manifest.key`；本次发布不代表已通过商店审核或已升级生产容器。

399 项自动测试、Lint、网页／服务端及扩展构建通过。[CPU 验证记录](https://github.com/SageSang/harbor-deck/blob/v1.4.28/docs/idle-cpu-validation-2026-10-12.json)。

## English

- Fix sustained high CPU usage while the navigation page is idle. Display settings were repeatedly written to the cache because validation changed property order, triggering another render and write. Identical content is now ignored, and cache notifications no longer republish stale settings.
- In isolated Linux Chrome with 120 test bookmarks, single-page main-thread busy time fell from 99.76% to 0.34%. Two pages fell from about 99.7% each to 0.23% and 0.35%, with no cache writes during the five-second idle samples. The affected Mac still needs verification after upgrading.
- For web pages and extension direct mode, update the server to `ghcr.io/sagesang/harbor-deck:1.4.28` and reload existing pages. For locally rendered new tabs, update the extension to 1.4.28. Keep existing ports, configuration mounts, addresses, tokens and bookmarks; no cache reset is needed.
- Chrome and Edge each include an unpacked ZIP and a `-store.zip` upload package. Store packages omit `manifest.key`. This release does not automatically update production containers or submit extensions to browser stores.

All 399 automated tests, lint, web/server builds and extension builds passed.
